# next-cache-trace

See which Next.js cache tags are produced, which mutations invalidate them, and where cached functions directly read request data.

A local TypeScript AST analyzer for Next.js 16 App Router. It provides a CLI, typed JavaScript API, ESLint integration, and text/JSON/SARIF/standalone HTML reports. No telemetry and no application code execution.

## Try the source checkout in 60 seconds

Node.js 20.19+ (ESLint 10 requires 22.13+ on the Node 22 line).

```bash
npm ci
npm run build
node bin/next-cache-trace.js audit examples/next16-cache-risks
node bin/next-cache-trace.js audit examples/next16-blog --format html --output artifacts/blog.html
```

The first command intentionally reports cache risks and exits 1. The working blog should have zero findings and a `posts` producer/invalidation relationship. Open `artifacts/blog.html` in a browser.

The public package has **not been published**. Once published, the equivalent command will be `npx next-cache-trace audit .`. Until then, use the checkout CLI or install a local tarball generated by `npm pack`.

## What it finds

```ts
import { cacheTag, cacheLife, updateTag } from 'next/cache';

export async function getPosts() {
  'use cache';
  cacheTag('posts');
  cacheLife('hours');
  return [];
}

export async function save() {
  updateTag('post'); // NCT001: observed producer is "posts", not "post".
}
```

| Rule | Default | Meaning |
| --- | --- | --- |
| NCT001 | warning | Invalidation has no observed literal producer in the scanned files. |
| NCT002 | error | Direct imported cookies()/headers() call inside a shared/remote cached function. |
| NCT003 | warning | Literal tag shared by multiple top-level route areas; a review signal. |
| NCT004 | error | Cache Components usage with statically disabled/missing configuration. |
| NCT005 | info | Cached function has no direct cacheLife call; default lifetime may be intentional. |
| NCT900 | info | Dynamic tag or unresolved options; relationship not inferred. |
| NCT901 | info | Exported Next configuration could not be statically resolved. |
| NCT902 | error | Source parsing failed. |

Named aliases, namespace imports, shadowed bindings, function directives and file-level exported functions are handled. Producers include literal `cacheTag`, `fetch(..., { next: { tags } })` and `unstable_cache(..., ..., { tags })`.

Reading `draftMode().isEnabled` is allowed by current Next.js documentation. Private caches allow request APIs. This tool does not check draft-mode enable/disable mutations or experimental private-cache configuration.

## Reports and CI exit codes

```bash
node bin/next-cache-trace.js audit /path/to/app --format json
node bin/next-cache-trace.js audit /path/to/app --format sarif --output artifacts/cache.sarif
node bin/next-cache-trace.js audit /path/to/app --format html --output artifacts/cache.html
node bin/next-cache-trace.js audit /path/to/app --fail-on warning
```

Exit 0: threshold not reached. Exit 1: findings reached the threshold. Exit 2: bad arguments, file I/O or configuration error. Default threshold is `error`; `none` disables finding-based failure, not tool errors. Existing output files need `--force`.

## Configuration and suppressions

Put `next-cache-trace.config.json` in the project being audited:

```json
{
  "include": ["app/**", "src/**", "lib/**"],
  "exclude": ["src/generated/**"],
  "rules": { "NCT003": "off", "NCT005": "info" }
}
```

Use `cacheComponents: true` here only to provide known configuration when Next config is dynamic. `--config` resolves relative to the audited project. `--exclude` and `--ignore-rule` are repeatable. Glob paths use forward slashes.

```ts
// next-cache-trace-disable-next-line NCT001 -- producer lives in another service
updateTag('external');
```

Ignored findings remain in the relationship graph. Default exclusions cover node_modules, .next, build outputs, declaration files, *.test.*, *.spec.* and config files. Symlinks are not followed.

## ESLint flat config

After publishing, install `next-cache-trace`, `eslint`, and `typescript-eslint` as dev dependencies. The companion `eslint-plugin-next-cache-trace` is an optional packaging alias and also requires the main package installed explicitly.

```js
// eslint.config.mjs
import tseslint from 'typescript-eslint';
import trace from 'next-cache-trace/eslint';
// Alternatively: import trace from 'eslint-plugin-next-cache-trace';

export default [{
  files: ['**/*.{js,jsx,ts,tsx}'],
  languageOptions: { parser: tseslint.parser },
  ...trace.configs.project,
  settings: {
    'next-cache-trace': { projectRoot: import.meta.dirname }
  }
}];
```

`recommended` runs file-local rules only (NCT002/NCT005/NCT900), suitable for fast editor feedback. `project` enables all rules and requires `projectRoot` for cross-file NCT001/NCT003 and config inference. Project mode rereads the project and caches AST results by source content; unsaved text in the current editor buffer overrides its disk version. Other unsaved files are not visible. It favors freshness over speed on large repositories.

ESLint maps informational findings to warnings because ESLint has no info level. Use normal ESLint rule severity settings and disable comments there. CLI JSON config controls CLI severity.

## What it does not prove

This is not a runtime cache tracer. It cannot prove hit/miss behavior, freshness, whether a branch executes, or whether a tag is intentionally shared. An observed literal edge is source evidence, not an execution trace.

It does not follow barrel re-exports, imported wrappers, indirect helper calls, arbitrary variable flow, CommonJS require bindings, MDX, or route consumer call graphs. Nested ordinary functions are analyzed separately and are not assumed to execute inside the outer cache. Code using those patterns can have missed findings. Dynamic Next config is reported as unknown rather than executed.

NCT001 is deliberately observational: external/dynamic producers and exclusions may explain it. Zero findings does not establish correctness, especially when the scan found no cache boundaries.

Targets Next.js 16 App Router. Pages Router, Edge-specific behavior, storage backends and live overlays are outside this release.
